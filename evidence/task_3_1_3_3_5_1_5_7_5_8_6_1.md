# KEV 模型、HTTP 接口和首版运行配置证据

日期：2026-09-23

## 实现范围

- `KevQwen3ForDecision` 复用 causal `Qwen3Model`，注册为只支持 `plugin` 的 pooling 模型；不创建 `lm_head`，不提供 `compute_logits`，因此引擎不会把它报告为生成模型。
- `KevPooler` 为 vLLM profiling/dummy warm-up 提供版本化且有效的最小 metadata。正常请求仍必须显式提交每题的 option/readout 索引，缺失或非法 metadata 会被拒绝。
- `POST /v1/systemone` 仅在模型架构为 `KevQwen3ForDecision` 时注册。请求由严格 Pydantic 模型一次性校验，未知字段（包括生成参数）、非法问题和非有限 JSON 数值在任何子请求提交前返回结构化 422。
- HTTP 层接入 `EngineClient.encode` 和 `PoolingParams(task="plugin")`，直接提交 token IDs 与逐题 metadata；输出保持输入问题顺序并返回规范模型 ID、answers、逻辑 input tokens、固定 KEV JSON 序列化 output tokens 和包含排队时间的 latency。
- 服务启动时执行一个合法 noul 决策 warm-up，成功后才设置 SystemOne ready；失败时保留未就绪状态并记录异常。
- 首版模型初始化拒绝非 TP=1/PP=1、非 eager、APC、chunked prefill、量化、运行时 LoRA、未显式匹配的 BF16/FP16，以及小于完整分支上限的 batch token budget。
- 普通非 KEV 模型不会挂载 SystemOne 路由；KEV 模型不会向 API server 报告 `generate` 能力，因此生成/聊天路由不会为该实例注册。
